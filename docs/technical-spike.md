# NocoBase 2.2.10 技术验证计划

本文件记录进入正式功能开发前必须验证的三个高风险点。结论必须以 NocoBase 2.2.10 实际构建和运行结果为准。

## 1. V2 统计行注入

目标：在不复制、不替换原生表格区块的前提下，通过 FlowEngine / TableBlockModel 扩展注入统计栏。

验收：

- 统计栏可位于表头下方或数据行下方；
- 列宽、固定列、横向滚动时保持对齐；
- 不影响选择列、操作列、分页和空状态；
- 多个表格区块配置彼此隔离。

当前判断：官方存在 TableBlockModel 和自定义表格区块示例，具备扩展入口；具体采用 flow 注入、模型扩展还是原生 Table summary 属性，需在 2.2.10 环境中验证后决定。

## 2. 查询条件继承

目标：统计请求复用当前 Table Block 已解析的查询参数，不建立第二套筛选系统。

必须覆盖：

- Filter 与 Data Scope；
- 快速筛选；
- URL、页面和当前记录变量；
- 关联上下文；
- 刷新、分页和数据变更事件。

验收：同一时刻表格查询与统计查询的有效 filter 一致；全部数据模式忽略 page/pageSize，当前页模式只计算已加载行。

## 3. ACL 下的服务端聚合

目标：聚合查询只统计当前用户有权读取的数据。

原则：

- 请求必须通过 NocoBase resource/action 上下文进入；
- 复用当前用户、角色、数据权限与字段权限；
- 禁止接收并执行任意 SQL、任意 collection 或未校验字段；
- 只允许白名单聚合函数和与字段类型匹配的操作；
- 统计失败不得阻断表格加载。

验收：使用管理员、受限角色和无权限角色分别测试，统计范围与表格可见范围一致。

## 结论状态（1.0.0 发布时复核）

- V2 统计行注入：**已验证**。通过 `TableBlockModel.props.summary` 注入统计行，渲染后校正 `<tfoot>` 位置，顶部 / 底部在任意区块高度下均生效。
- 查询条件继承：**已验证**。统计请求复用表格的 `getRequestOptions()` 参数（filter、数据范围、变量），并忽略 page / pageSize；当前页模式在浏览器端计算已加载行。
- ACL 服务端聚合：**已验证**。`tableSummary` 经 `acl.actionAlias` 映射到 `view`，复用数据范围与字段白名单，并校验字段存在性、字段类型与字段查看权限。

> 本文档记录 1.0.0 前的技术验证计划，结论已复核，保留作为设计依据。
